## 🔴 Наступне — велике

### Офлайн-робота каси (вимога власника, 2026-07-05)
Каса має працювати без інтернету, а після відновлення зв'язку — вивантажити
все на сервер.

Ескіз рішення:
1. **Локальна черга операцій** (IndexedDB): коли API недоступний, операція
   зберігається локально зі статусом `pending_sync`, UI показує банер
   «ОФЛАЙН · N операцій в черзі». Каса рахує баланс локально (ledger уже
   дзеркальний на фронті — `lib/shift-balance.ts`).
2. **Ідемпотентність**: кожна операція отримує `clientId` (uuid) ще на фронті;
   бекенд приймає його і при повторі (ретрай після збою) не створює дубля
   (unique index на `clientId`).
3. **Синк**: фоновий цикл — при відновленні зв'язку шле чергу по одній,
   у порядку створення, з реальним `createdAt` з фронта (бекенд приймає
   `createdAt` лише для синку офлайн-черги).
4. **Обмеження офлайну** (щоб не розвалити цілісність): в офлайні дозволені
   лише операції обміну та рух готівки «Інше»; передачі, USDT (глобальний банк),
   рух «Банк», закриття зміни — тільки онлайн.
5. **Конфлікти**: сторно/редагування в офлайні — заборонені; курс фіксується
   локально останній відомий.
6. PWA/service worker — щоб сторінка каси відкривалась без мережі.

Оцінка: найбільша фіча беклогу; чіпає фронт (черга, банер, синк), бекенд
(clientId, createdAt для синку), схему (unique clientId).

5. Розбити `CashierPage.tsx` (~1000 рядків) на компоненти
6. Спільний пакет для дзеркальних утиліт фронт/бек (ledger вже звів головне)
